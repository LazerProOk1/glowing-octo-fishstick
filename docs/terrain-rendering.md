# Топографический рендер карты: математика светотени и новые типы

Шаг 1.5 — переписан генератор и Canvas-рендерер. Ниже математика hillshading,
новые типы и пайплайн, по которому теперь собирается карта.

## 1. Новые типы — `src/types/world.ts`

```ts
export type Biome =
  | 'ocean' | 'coast' | 'plains' | 'forest' | 'mountains'
  | 'desert' | 'tundra' | 'swamp' | 'volcanic';

/** Визуальный класс рельефа: один биом может рисоваться как холмы, скалы или снег */
export type Surface =
  | 'deepOcean' | 'shallowWater' | 'beach' | 'plains' | 'tundra'
  | 'forest' | 'taiga' | 'hills' | 'mountains' | 'snow'
  | 'desert' | 'swamp' | 'volcanic';

export type ResourceType = 'none' | 'wood' | 'stone' | 'iron' | 'gold' | 'fish' | 'grain';

export interface Tile {
  elevation: number;    // 0..100
  moisture: number;     // 0..100
  temperature: number;  // °C, -30..40
  fertility: number;    // 0..100
  biome: Biome;
  surface: Surface;
  river: boolean;
  resource: ResourceType;
  ownerId: string | null;
}

export interface World {
  width: number;
  height: number;
  seed: number;
  tiles: Tile[][];          // tiles[y][x]
  tick: number;
  /** Сглаженная высота 0..100: поверхности, изолинии, батиметрия */
  elevationMap: Float32Array;
  /** Влажность 0..100 и температура °C — тоже поднимаются до пикселя */
  moistureMap: Float32Array;
  temperatureMap: Float32Array;
  /** Высота с мезо- и микрорельефом: только светотень и сток */
  reliefMap: Float32Array;
  /** D8: сколько тайлов стекает через тайл */
  flowAccumulation: Float32Array;
  /** D8: индекс тайла-приёмника, -1 если сток обрывается */
  flowDownstream: Int32Array;
}
```

Два поля высот — ключевое решение: шум микрорельефа даёт фактуру склонов и
изгибы рек, но не участвует в классификации поверхностей, поэтому пляжи и
берега остаются чистыми полосами, а не крапом.

`src/types/viewport.ts` и `src/lib/math.ts`:

```ts
export interface Viewport { offsetX: number; offsetY: number; zoom: number }

export function clamp(value: number, min: number, max: number): number
export function lerp(from: number, to: number, t: number): number
export function smoothstep(edge0: number, edge1: number, value: number): number
```

## 2. Математика hillshading

Обозначим высоту тайла `h(x, y)` в условных единицах 0..100, `k` — вертикальное
преувеличение, `s` — сила светотени.

**Перепад высот (центральные разности):**

```
gx = (h(x+1, y) − h(x−1, y)) / 2 · k
gy = (h(x, y+1) − h(x, y−1)) / 2 · k
```

**Нормаль поверхности** (ось X — восток, Y — вниз/юг, Z — вверх):

```
n = (−gx, −gy, 1) / √(gx² + gy² + 1)
```

**Источник света** — северо-запад, азимут `az = 315°` (по часовой от севера),
высота `alt = 45°`:

```
L = ( cos(alt)·sin(az), −cos(alt)·cos(az), sin(alt) )
  = ( −0.5, −0.5, 0.7071 )
```

Знак `−cos(az)` нужен потому, что на экране север — это `−Y`: для азимута 315°
горизонтальная составляющая равна `(−0.7071, −0.7071)` в координатах (восток, юг).

**Освещённость и нормировка:**

```
illum = max(0, n · L) = (−gx·Lx − gy·Ly + Lz) / √(gx² + gy² + 1)
shade = illum / Lz          // плоская поверхность → shade = 1
factor = clamp(1 + s·(shade − 1), 0.88, 1.10)
RGB' = RGB · factor
```

Формула из задания `light = sin(angle)·dx + cos(angle)·dy` — это линеаризация
скалярного произведения для малых уклонов: при `alt = 45°`, `az = 315°`
`n·L ≈ 0.5·gx + 0.5·gy + 0.7071`. Нормированный вариант выбран потому, что он
не «пересвечивает» крутые склоны и оставляет плоские равнины строго на базовом
цвете палитры (`shade = 1`), иначе вся карта уезжает в светлое.

Значения: `k = 0.6`, `s = 0.55`, диапазон множителя `0.88..1.10`. Светотень
считается по тайлам (`Float32Array`, 1 значение на тайл) и билинейно
интерполируется по пикселям, поэтому склоны выглядят плавно, а не 4-пиксельными
квадратами.

```
shadeField = Float32Array(width · height)      // из src/simulation/hillshade.ts
factor(x, y) = bilinear(shadeField, (x+0.5)/4 − 0.5, (y+0.5)/4 − 0.5)
```

## 3. Генерация: что изменилось

**Domain warping** — координаты выборки сами смещаются низкочастотным шумом:

```
wx = x + A · fbm(noiseA, x, y),   wy = y + A · fbm(noiseB, x, y),   A = 34
c  = (fbm(noiseC, wx, wy, 5 окт., f = 0.011) + 1) / 2
```

**Материковый спад** (мягкий, чтобы суша не выходила за кадр):

```
d = min(1, √(0.9·dx² + 0.9·dy²)),  dx, dy ∈ [−1, 1]
m = 1 − d³
shaped = c · (0.15 + 0.85·m)
```

**Хребты (ridged noise)** — узкие гребни вместо круглых блобов:

```
ridge = Σ (1 − |noise(x·f·lⁱ, y·f·lⁱ)|)² · wᵢ · aᵢ  /  Σ aᵢ     // 0..1, wᵢ — ridged-вес
inland = smoothstep(0.25, 0.62, shaped)
rawElevation = 0.6·shaped + 1.6·ridge²·inland
```

Квадрат ridge сужает гребни в цепи, `inland` не пускает горы в море.

**Квантильное отображение** — сырое поле раскладывается на целевую функцию
распределения, поэтому доли зон стабильны для любого сида: 40% море, 2.5% пляж,
~40% равнины, ~9% холмы, ~4.5% горы, ≤1% снег, ~8% пустыня.

**Климат:**

```
lat = |y/(H−1) − 0.5| · 2                    // 0 — экватор, 1 — полюс
T = 30 − 38·lat^1.9 − 0.13·h + noise·3.5
```

**Реки** — не «ручьи из точки А в точку Б», а гидрологическая сеть:

1. Для каждого тайла выбирается приёмник D8: сосед с минимальной высотой,
   при равенстве — с шумовой поправкой `meander = 0.8` (это и даёт меандры).
2. Тайлы сортируются по высоте, сток аккумулируется в порядке убывания:
   `acc[down] += acc[t]`.
3. Река рисуется там, где `acc ≥ 45` (0.5% площади), ширина 1 px, у устья 2 px.

Результат — дендритная сеть: истоки в горах, притоки сливаются, русла идут по
долинам и впадают в море.

**Микрорельеф** (только для светотени и стока):

```
reliefMap = clamp(h + 2.4·fbm(f = 0.055) + 1.0·fbm(f = 0.3), 0, 100)
```

## 4. Рендер: кэш и палитра

`bakeMap(world)` один раз собирает `Uint8ClampedArray` RGBA размером
`600×400` (4 px на тайл). `MapRenderer` кладёт его в `ImageData` offscreen-канвы,
дальше кадр — один `drawImage`. Панорама и зум не пересчитывают ни шум, ни свет.

Порядок обработки пикселя:

1. Высота пикселя из билинейно увеличенного `elevationMap` — гладкая береговая
   линия вместо лесенки из 4 px.
2. Море (`h < 24`): батиметрия — плавный переход `deepOcean → shallowWater` по
   `smoothstep(h / 24)`, у берега кайма пены `#93CFE0` (полоса 0.8 ед. высоты).
3. Суша: класс поверхности определяется **на пикселе** из интерполированных
   `elevation`, `moisture`, `temperature` (`surfaceAt`), а не из тайла. Поэтому
   границы лесов, песка и снега идут плавными кривыми, а не по сетке 4×4.
4. Светотень: `factor` из hillshade.
5. Изолинии: каждые 5 единиц высоты, `×0.87`; каждая пятая (25 ед.) — `×0.80`.
6. Береговая линия: полоса `h < 24.9` затемняется `×0.84`.
7. Текстура: микро-шум ±3.5% и крупный ±2% по тайлу.
8. Реки — отдельный векторный слой: `buildRiverPolylines` собирает цепочки из
   D8-сети, `MapRenderer` рисует их `quadraticCurveTo` + `stroke()` в экранных
   координатах, поэтому линии остаются гладкими и чёткими на любом зуме.
   Ширина клампится в 1.1–3.5 экранных пикселя.

Поля высот, влажности и температуры поднимаются до пикселя через
`upsampleField(..., smoothed = true)`: веса билинейной интерполяции проходят
через `t²(3−2t)`, что убирает «ромбовидные» артефакты на диагональных границах.
Масштабирование слоя включено (`imageSmoothingEnabled = true`), поэтому при
зуме карта не рассыпается на блоки 4×4.

## 5. Интерфейс

Карта занимает весь экран (`h-screen w-screen`, без отступов), панель плавающая:
`absolute inset-x-0 top-0 h-12`, `bg-white/80`, `backdrop-blur-md`,
`border-b border-zinc-200`, без теней. Кнопка «Новый мир» — `bg-zinc-900`,
`hover:bg-zinc-800`, `rounded-md`, `text-sm font-medium`. Ползунок сида: трек
3 px `bg-zinc-200`, заполнение `bg-zinc-900`, кнопка 12 px. Акцентный синий
`#2563EB` из первой итерации убран полностью.

## 6. Производительность

Замеры в Node на 150×100 (V8, без прогрева):

- `generateWorld`: 75–90 мс (шум, квантили, гидрология)
- `bakeMap`: 55–70 мс (240k пикселей, светотень, изолинии, реки)
- кадр панорамы/зума: один `drawImage`, стабильные 60 fps

Генерация вызывается только на «Новый мир» или на коммит ползунка сида.

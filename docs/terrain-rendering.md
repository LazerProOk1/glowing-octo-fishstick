# Топографический рендер карты: математика светотени и новые типы

Шаг 1.5 — переписан генератор и Canvas-рендерер. Ниже математика hillshading,
новые типы и пайплайн, по которому теперь собирается карта.

## 1. Новые типы — `src/types/world.ts`

```ts
export type Biome =
  | 'ocean' | 'coast' | 'plains' | 'forest' | 'mountains'
  | 'desert' | 'tundra' | 'swamp' | 'volcanic';

/** Визуальный класс рельефа: один биом может рисоваться как холмы, скалы или снег */
export type Surface =
  | 'deepOcean' | 'shallowWater' | 'beach' | 'plains' | 'tundra'
  | 'forest' | 'taiga' | 'hills' | 'mountains' | 'snow'
  | 'desert' | 'swamp' | 'volcanic';

export type ResourceType = 'none' | 'wood' | 'stone' | 'iron' | 'gold' | 'fish' | 'grain';

export interface Tile {
  elevation: number;    // 0..100
  moisture: number;     // 0..100
  temperature: number;  // °C, -30..40
  fertility: number;    // 0..100
  biome: Biome;
  surface: Surface;
  river: boolean;
  resource: ResourceType;
  ownerId: string | null;
}

export interface World {
  width: number;
  height: number;
  seed: number;
  tiles: Tile[][];          // tiles[y][x]
  tick: number;
  /** Сглаженная высота 0..100: поверхности, изолинии, батиметрия */
  elevationMap: Float32Array;
  /** Влажность 0..100 и температура °C — тоже поднимаются до пикселя */
  moistureMap: Float32Array;
  temperatureMap: Float32Array;
  /** Высота с мезо- и микрорельефом: только светотень и сток */
  reliefMap: Float32Array;
  /** D8: сколько тайлов стекает через тайл */
  flowAccumulation: Float32Array;
  /** D8: индекс тайла-приёмника, -1 если сток обрывается */
  flowDownstream: Int32Array;
}
```

Два поля высот — ключевое решение: шум микрорельефа даёт фактуру склонов и
изгибы рек, но не участвует в классификации поверхностей, поэтому пляжи и
берега остаются чистыми полосами, а не крапом.

`src/types/viewport.ts` и `src/lib/math.ts`:

```ts
export interface Viewport { offsetX: number; offsetY: number; zoom: number }

export function clamp(value: number, min: number, max: number): number
export function lerp(from: number, to: number, t: number): number
export function smoothstep(edge0: number, edge1: number, value: number): number
```

## 2. Математика hillshading

Обозначим высоту тайла `h(x, y)` в условных единицах 0..100, `k` — вертикальное
преувеличение, `s` — сила светотени.

**Перепад высот (центральные разности):**

```
gx = (h(x+1, y) − h(x−1, y)) / 2 · k
gy = (h(x, y+1) − h(x, y−1)) / 2 · k
```

**Нормаль поверхности** (ось X — восток, Y — вниз/юг, Z — вверх):

```
n = (−gx, −gy, 1) / √(gx² + gy² + 1)
```

**Источник света** — северо-запад, азимут `az = 315°` (по часовой от севера),
высота `alt = 45°`:

```
L = ( cos(alt)·sin(az), −cos(alt)·cos(az), sin(alt) )
  = ( −0.5, −0.5, 0.7071 )
```

Знак `−cos(az)` нужен потому, что на экране север — это `−Y`: для азимута 315°
горизонтальная составляющая равна `(−0.7071, −0.7071)` в координатах (восток, юг).

**Освещённость и нормировка:**

```
illum = max(0, n · L) = (−gx·Lx − gy·Ly + Lz) / √(gx² + gy² + 1)
shade = illum / Lz          // плоская поверхность → shade = 1
factor = clamp(1 + s·(shade − 1), 0.88, 1.10)
RGB' = RGB · factor
```

Формула из задания `light = sin(angle)·dx + cos(angle)·dy` — это линеаризация
скалярного произведения для малых уклонов: при `alt = 45°`, `az = 315°`
`n·L ≈ 0.5·gx + 0.5·gy + 0.7071`. Нормированный вариант выбран потому, что он
не «пересвечивает» крутые склоны и оставляет плоские равнины строго на базовом
цвете палитры (`shade = 1`), иначе вся карта уезжает в светлое.

Значения: `k = 0.6`, `s = 0.55`, диапазон множителя `0.88..1.10`. Светотень
считается по тайлам (`Float32Array`, 1 значение на тайл) и билинейно
интерполируется по пикселям, поэтому склоны выглядят плавно, а не 4-пиксельными
квадратами.

```
shadeField = Float32Array(width · height)      // из src/simulation/hillshade.ts
factor(x, y) = bilinear(shadeField, (x+0.5)/4 − 0.5, (y+0.5)/4 − 0.5)
```

## 3. Генерация: что изменилось

**Domain warping** — координаты выборки сами смещаются низкочастотным шумом:

```
wx = x + A · fbm(noiseA, x, y),   wy = y + A · fbm(noiseB, x, y),   A = 24
c  = (fbm(noiseC, wx, wy, 5 окт., f = 0.0155, lacunarity 2.05, gain 0.5) + 1) / 2
shaped = c
```

Форму суши задаёт только низкочастотный `fbm`: на одном сиде получается 2–3
континента с заливами, внутренними морями и архипелагами.

**Мягкая виньетка краёв** — не круг, а суперэллипс, повторяющий рамку карты:

```
nx, ny ∈ [−1, 1]
r = (|nx|³ + |ny|³)^(1/3) + noise·0.1          // шум рвёт контур виньетки
mask = 1 − smoothstep(0.76, 1.04, r)            // 1 в центре, 0 на краю

// после квантильного отображения:
elevation = clamp(elevation·mask − (1 − mask)·46, 0, 100)
```

Виньетка применяется **после** квантилей: бюджет воды остаётся за континентальным
шумом, поэтому проливы и внутренние моря не съедаются, а рамка карты всегда
становится глубоким океаном. Итог — ~60% воды, суша не касается краёв.

**Хребты (ridged noise)** — узкие гребни вместо круглых блобов:

```
ridge = Σ (1 − |noise(x·f·lⁱ, y·f·lⁱ)|)² · wᵢ · aᵢ  /  Σ aᵢ     // 0..1, wᵢ — ridged-вес
inland = smoothstep(0.45, 0.75, shaped)
rawElevation = 0.6·shaped + 1.6·ridge²·inland
```

Квадрат ridge сужает гребни в цепи, `inland` не пускает горы в море.

**Квантильное отображение** — сырое поле раскладывается на целевую функцию
распределения, поэтому доли зон стабильны для любого сида: 40% море, 2.5% пляж,
~40% равнины, ~9% холмы, ~4.5% горы, ≤1% снег, ~8% пустыня.

**Климат:**

```
lat = |y/(H−1) − 0.5| · 2                    // 0 — экватор, 1 — полюс
T = 30 − 38·lat^1.9 − 0.13·h + noise·3.5
```

**Реки** — не «ручьи из точки А в точку Б», а гидрологическая сеть:

1. Для каждого тайла выбирается приёмник D8: сосед с минимальной высотой,
   при равенстве — с шумовой поправкой `meander = 0.8` (это и даёт меандры).
2. Тайлы сортируются по высоте, сток аккумулируется в порядке убывания:
   `acc[down] += acc[t]`.
3. Река отмечается там, где `acc ≥ 45` (0.5% площади): флаг `tile.river`.
   Вектором реки не рисуются — при bake канал вдавливается в рельеф
   (см. раздел 4).

Результат — дендритная сеть: истоки в горах, притоки сливаются, русла идут по
долинам и впадают в море.

**Микрорельеф** (только для светотени и стока):

```
reliefMap = clamp(h + 2.4·fbm(f = 0.055) + 1.0·fbm(f = 0.3), 0, 100)
```

## 4. Плоская заливка и векторные реки

Дизеринг убран полностью: никакого `hash2D` по пикселю, никакой «текстуры»
шумом. Пиксель классифицируется по интерполированным `elevation` / `moisture` /
`temperature`, поэтому границы биомов — плавные кривые, а заливка внутри
биома ровная, как на политической карте. Объём даёт только hillshading по
`reliefMap`, плюс тонкие изолинии (`CONTOUR_STEP = 5`, затемнение 0.93) и
затемнение кромки берега.

Реки больше не впечатаны растр-маской: `src/rendering/riverPaths.ts` собирает
из `tile.river` + `flowDownstream` полилинии по центрам тайлов (от истока к
устью, устье доводится до моря), а `MapRenderer` рисует их как векторы
кривыми через средние точки. Толщина растёт с `flowAccumulation`:
`1 + log10(1 + acc) · 0.5`, в пределах 1–2.6 экранных пикселя.

## 5. Провинции

`src/simulation/provinces.ts` — 8-связный multi-source Dijkstra по сетке тайлов.

- 720 центров (`PROVINCE_TARGET_COUNT`) на 150×100: клетки по ~8 тайлов.
- Центры выбираются по `hash2D` с шагом `minSeedSpacing = 5`, шаг ослабляется
  до 1, пока не наберётся нужное число, — так клетки равномерные, но не сетка.
- **Только суша**: `isLandTile` = `elevation >= SEA_LEVEL (24)`. Рост немедленно
  останавливается на воде, поэтому у воды всегда `provinceId = -1`, а береговая
  линия и есть граница провинции.
- Стоимость: равнина `1`, пустыня `1.3`, лес `1.4`, тундра `1.6`, болото `2.2`,
  вулкан `4`, холм `2.5`, гора `6`; плюс шум
  `noise2D(x·0.17, y·0.17)·1.5` — из-за него границы рваные, а не квадратные.
  Ограничения по суммарной стоимости нет: вся суша распределена.

`src/rendering/provinceBorders.ts` превращает лесенку по рёбрам тайлов в гладкие
линии:

1. **Рёбра** — границы берутся там, где два соседних тайла суши принадлежат
   разным провинциям; стык с водой не рисуется вовсе.
2. **Элементарные цепочки** — граф границ режется в узлах, где сходятся три и
   более области, **и в узлах на береговой линии**: иначе провинция проходит
   только часть цепочки и полигон подсветки перестаёт совпадать с линией.
3. **Упрощение** — Дуглас-Пекер с допуском `1` тайл сворачивает квадратную
   лесенку в несколько длинных звеньев.
4. **Сдвиг вершин** — каждая вершина смещается на ±0.3 тайла; смещение берётся
   из `hash2D` по координате самой вершины, поэтому две провинции, разделяющие
   границу, получают одинаковый сдвиг.

Сглаживание живёт в рендере и не использует сплайнов вовсе — это кривые через
средние точки:

```
moveTo(p[0]);
for (i = 0; i < n - 1; i++) {
  quadraticCurveTo(p[i], midpoint(p[i], p[i + 1]));
}
lineTo(p[n - 1]);
```

Каждая вершина становится контрольной точкой, а кривая проходит через середины
рёбер. Углов не остаётся ни на одном стыке, и никакой параметризации, которая
может дать петлю или «мыло». Замкнутые контуры (полигон провинции, маска суши)
обходятся так же, но стартуют с середины последнего ребра.

Береговая линия для маски считается **marching squares** по `elevationMap` с
порогом `SEA_LEVEL`: контур идёт по интерполированным точкам пересечения и
совпадает с берегом, нарисованным в bake, а не по границам тайлов.

`MapRenderer` собирает `Path2D` в координатах тайлов, умноженных на
`PIXELS_PER_TILE`:

- `landPath` — силуэт суши (`context.clip(landPath, 'evenodd')`, чтобы внутренние
  озёра стали дырками);
- `borderPath` — все цепочки границ (`rgba(0, 0, 0, 0.35)`, `lineWidth = 0.8 / zoom`);
- `highlightPath` — заливка выбранной провинции (`rgba(255, 255, 255, 0.2)`);
- `riverPaths` — полилинии рек со своей толщиной.

И подсветка, и обводка, и реки рисуются **внутри клипа по суше**, поэтому
сплайн, который вылез за берег, обрезается ровно по плавной береговой линии.
Полигон подсветки собирается из тех же точек цепочек, что и обводка (кэш по
индексу цепочки), так что заливка не «гуляет» относительно линии.

Форма клеток выравнивается **релаксацией Ллойда** в `provinces.ts`: после
каждого прохода Dijkstra центр провинции переезжает в центр масс своей
территории (3 итерации, снап к ближайшему свободному тайлу суши). Случайный
разброс превращается в ровные соты.

## 6. Рендер: кэш и палитра

`bakeMap(world, { pixelsPerTile })` один раз собирает `Uint8ClampedArray` RGBA
размером `1500×1000` (по умолчанию 10 px на тайл; параметр ограничен 4–16).
Канвас растёт по `devicePixelRatio` (`width/height = css × dpr`, CSS — 100%), а
рисование идёт с трансформом `dpr` — поэтому на ретине карта не мылится. Слой
рисуется с `imageSmoothingQuality = 'high'`. `MapRenderer` кладёт его в `ImageData` offscreen-канвы,
дальше кадр — один `drawImage`. Панорама и зум не пересчитывают ни шум, ни свет.

Порядок обработки пикселя:

1. Высота пикселя из билинейно увеличенного `elevationMap` — гладкая береговая
   линия вместо лесенки из 4 px.
2. Море (`h < 24`): батиметрия — плавный переход `deepOcean → shallowWater` по
   `smoothstep(h / 24)`, у берега кайма пены `#93CFE0` (полоса 0.8 ед. высоты).
3. Суша: класс поверхности определяется **на пикселе** из интерполированных
   `elevation`, `moisture`, `temperature` (`surfaceAt`), а не из тайла. Поэтому
   границы лесов, песка и снега идут плавными кривыми, а не по сетке 4×4.
4. Светотень: `factor` из hillshade.
5. Изолинии: каждые 5 единиц высоты, `×0.87`; каждая пятая (25 ед.) — `×0.80`.
6. Береговая линия: полоса `h < 24.9` затемняется `×0.84`.
7. Текстура: микро-шум ±3.5% и крупный ±2% по тайлу.
8. Реки — отдельный векторный слой: `buildRiverPolylines` собирает цепочки из
   D8-сети, `MapRenderer` рисует их `quadraticCurveTo` + `stroke()` в экранных
   координатах, поэтому линии остаются гладкими и чёткими на любом зуме.
   Ширина клампится в 1.1–3.5 экранных пикселя.

Поля высот, влажности и температуры поднимаются до пикселя через
`upsampleField(..., smoothed = true)`: веса билинейной интерполяции проходят
через `t²(3−2t)`, что убирает «ромбовидные» артефакты на диагональных границах.
Масштабирование слоя включено (`imageSmoothingEnabled = true`), поэтому при
зуме карта не рассыпается на блоки 4×4.

Палитра (`src/rendering/palette.ts`):

| Класс | Hex | Класс | Hex |
|---|---|---|---|
| deepOcean | `#1B4965` | hills | `#8F9A6C` |
| shallowWater | `#62B6CB` | mountains | `#6C757D` |
| beach | `#E8D8B0` | snow | `#F8F9FA` |
| plains | `#76A035` | river | `#5FA8D3` |
| forest | `#386641` | foam | `#93CFE0` |

Добавлены четыре значения, которых не было в задании, но без них палитра не
покрывает все биомы: `desert #DCC79B`, `tundra #A9B3A2`, `swamp #5F7A5C`,
`volcanic #635B55`.

Гипсометрические ступени (выше 50, `HIGHLAND_BANDS`):
`50 → #8F9A6C`, `60 → #7E8777`, `70 → #6C757D`, `82 → #666F77`,

на границе леса и снега не появлялись белые пятна при `temp ≈ −2 °C`.

## 7. Интерфейс

Карта занимает весь экран (`h-[100dvh] w-screen`, без отступов и полей),
`#root`/`body` без `padding` и `margin`, фон приложения — глубокий океан
`#1B4965`. Canvas вписывается по принципу **cover**, поэтому карта уходит под
верхнюю панель и не оставляет серой рамки. Верхняя панель плавающая:
`absolute inset-x-0 top-0 h-12`, `bg-white/80`, `backdrop-blur-md`,
`border-b border-zinc-200`, без теней. Кнопка «Новый мир» — `bg-zinc-900`,
`hover:bg-zinc-800`, `rounded-md`, `text-sm font-medium`. Ползунок сида: трек
3 px `bg-zinc-200`, заполнение `bg-zinc-900`, кнопка 12 px. Акцентный синий
`#2563EB` из первой итерации убран полностью.

Панель провинции — справа, `w-[300px]`, `rounded-lg border border-zinc-200`,
`bg-white/85 backdrop-blur-md`: ID, доминирующий биом, население (`0`),
принадлежность («Нет»), число тайлов. Клик по суше выбирает провинцию, клик по
морю снимает выбор.

## 8. Производительность

Замеры в Node на 150×100 (V8, без прогрева):

- `generateWorld`: 145–160 мс (шум, квантили, гидрология, 720 провинций,
  4 прохода Dijkstra из-за релаксации Ллойда)
- `bakeMap`: 220–230 мс (1.5M пикселей, светотень, изолинии, без шума)
- векторные границы: ~1900 цепочек, ~50 мс на построение (один раз на мир)
- реки: ~15 полилиний, строятся вместе с границами
- подсветка провинции: полигон строится по клику и кэшируется
- кадр панорамы/зума: `drawImage` + два `stroke/fill`, стабильные 60 fps

Генерация вызывается только на «Новый мир» или на коммит ползунка сида.
